Architecture

CDH Bridge is a microservices middleware layer that sits between your customer touchpoints and Pega CDH. Each service handles one responsibility, communicates via Kafka, and exposes a clean REST API.

Customer Touchpoints CDH Bridge Pega CDH ────────────────── ─────────── ──────── Web / Mobile SDK ──────► Event Collector :3001 ──────► IH Events CRM (Salesforce) ──────► Connector Pack :3005 ──────► DWH (Snowflake) ──────► Profile Router :3002 ──────► Customer Profile Call Centre ──────► │ Kafka (cdh-events, NBA Engine cdh-profiles, │ cdh-consent, ▼ cdh-feedback) Feedback Loop :3003 Consent Svc :3004

Service Summary

ServicePortResponsibilityKey Endpoint
Event Collector3001Ingest & map behavioural events → IH schema → KafkaPOST /v1/events
Profile Router3002Unified customer profile store in Redis; dedup & mergeGET /v1/profiles/:id
Feedback Loop3003Record NBA outcomes; calculate lift vs baselinePOST /v1/feedback
Consent Service3004Propagate opt-out/GDPR/CCPA with audit trailPOST /v1/consent/optout
Connector Service300515 pre-built connectors: CRM, DWH, CCaaS → KafkaGET /v1/connectors
Mock Pega CDH3010Simulates Pega CDH API for local dev & demosPOST /api/events
Dashboard3000Real-time monitoring UI (Next.js)GET /

Kafka Topics

TopicProducerConsumerPayload
cdh-eventsEvent CollectorMock Pega CDHIH Event objects
cdh-profilesProfile Router, ConnectorsProfile RouterUnified profile deltas
cdh-consentConsent ServiceAll servicesConsent change events
cdh-feedbackFeedback LoopProfile RouterNBA outcome records
ℹ️
Local dev uses KafkaJS with an in-process broker mock. You don't need a real Kafka cluster to run locally — the KAFKA_MOCK=true flag in .env.example enables this automatically.

Feature 1: Event Collector :3001

📡
Receives behavioural events from any channel, maps them to Pega CDH Interaction History schema, and publishes to the cdh-events Kafka topic. Supports both real-time single events and high-throughput batch ingestion.

CDH IH Event Type Mapping

Your eventTypeCDH IH TypeDescription
page_viewIH.WebBrowseCustomer browsed a page
product_viewIH.ProductViewViewed a product detail page
app_openIH.AppSessionOpened mobile app
form_submitIH.InteractionSubmitted a form
purchaseIH.ConversionCompleted a purchase
call_startIH.CallStartCalled contact centre
offer_acceptIH.OfferAcceptedAccepted an NBA offer
offer_rejectIH.OfferRejectedRejected an NBA offer
loginIH.LoginCustomer logged in
1
Track a web event
bash
curl -X POST http://localhost:3001/v1/events \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "CUST-001",
    "eventType": "product_view",
    "channel": "web",
    "properties": {
      "product": "home-loan",
      "rate": "4.2%",
      "page": "/products/mortgages"
    }
  }'

Expected Response

json
{
  "success": true,
  "accepted": true,
  "correlationId": "89202c7a-4f1b-4e3a-9c21-d8e7f3a1b002",
  "ihEventType": "IH.ProductView",
  "kafka": {
    "topic": "cdh-events",
    "partition": 0,
    "offset": "42"
  }
}
2
Track an anonymous visitor (cookieId only)
bash
curl -X POST http://localhost:3001/v1/events \
  -H "Content-Type: application/json" \
  -d '{
    "cookieId": "ck-abc123",
    "eventType": "page_view",
    "channel": "web",
    "properties": { "page": "/home-loans" }
  }'
ℹ️
Anonymous events are stored against the cookieId until a login event stitches them to a known customerId.
3
Login event (triggers identity stitch)
bash
curl -X POST http://localhost:3001/v1/events \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "CUST-001",
    "cookieId": "ck-abc123",
    "eventType": "login",
    "channel": "web"
  }'
✅
This fires the identity stitch — all pre-login events from ck-abc123 are merged into CUST-001's Interaction History profile in Pega CDH.
4
Batch events (high-throughput ingestion)
bash
curl -X POST http://localhost:3001/v1/events/batch \
  -H "Content-Type: application/json" \
  -d '{
    "events": [
      {
        "customerId": "CUST-001",
        "eventType": "page_view",
        "channel": "web"
      },
      {
        "customerId": "CUST-001",
        "eventType": "product_view",
        "channel": "web",
        "properties": { "product": "home-loan" }
      }
    ]
  }'
5
Get CDH IH schema reference
bash
curl http://localhost:3001/v1/events/schema

Returns the full JSON schema for all supported IH event types, including required/optional fields per type.

6
Check service health
bash
curl http://localhost:3001/health

Feature 2: Profile Router :3002

👤
Maintains unified customer profiles in Redis. Fetches from all connected source systems, deduplicates, and serves to Pega CDH in sub-100ms. Merge conflicts are automatically resolved by confidence scoring; low-confidence merges are queued for review.
1
Create / upsert a profile
bash
curl -X POST http://localhost:3002/v1/profiles \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "CUST-001",
    "email": "alice@bank.com",
    "phone": "+61 412 345 678",
    "firstName": "Alice",
    "lastName": "Smith",
    "ltv": 84500,
    "segments": ["HighValue", "MortgageHolder"],
    "_source": "Salesforce"
  }'

Response includes merge action

json
{
  "success": true,
  "action": "CREATED",
  "customerId": "CUST-001",
  "confidence": 1.0
}
CREATED MERGED REVIEW_QUEUED
2
Get a unified profile
bash
curl http://localhost:3002/v1/profiles/CUST-001
3
Get profile stats
bash
curl http://localhost:3002/v1/profiles/stats

Returns total profiles, merge rate, pending reviews, avg confidence score, and Redis memory usage.

4
Trigger manual profile merge (data enrichment)
bash
curl -X POST http://localhost:3002/v1/profiles/CUST-001/merge \
  -H "Content-Type: application/json" \
  -d '{
    "ltv": 92000,
    "segments": ["Premium"],
    "_source": "Snowflake"
  }'
5
Delete a profile (GDPR erasure)
bash
curl -X DELETE http://localhost:3002/v1/profiles/CUST-001
⚠️
This immediately removes all profile data from Redis and publishes a PROFILE_DELETED event to cdh-profiles. For full GDPR erasure, also trigger the Consent Service GDPR endpoint.
6
Get profile change history
bash
curl http://localhost:3002/v1/profiles/CUST-001/history

Returns a timestamped audit log of all field changes, source systems, and merge actions.

Feature 4: Consent Service :3004

🔒
Manages consent propagation. A single opt-out event fans out to Pega CDH + all connected systems in <500ms. GDPR and CCPA compliant with an immutable, append-only audit trail stored in Redis Streams.
1
Marketing opt-out
bash
curl -X POST http://localhost:3004/v1/consent/optout \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "CUST-001",
    "channels": ["email", "sms"],
    "source": "preference-centre"
  }'
✅
Propagates to Pega CDH in <500ms. All future CDH events for this customer suppress email and SMS channels automatically.
2
GDPR Right to Erasure
bash
curl -X POST http://localhost:3004/v1/consent/gdpr-erasure \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "CUST-001",
    "requestId": "gdpr-req-001",
    "requestedAt": "2026-06-08T10:00:00Z",
    "verificationToken": "verified"
  }'
⚠️
Triggers full erasure across Profile Router, Event Collector history, and Pega CDH. SLA: 72 hours (configurable). Audit log is retained as an anonymised erasure record.
3
CCPA Do Not Sell
bash
curl -X POST http://localhost:3004/v1/consent/ccpa-dns \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "CUST-001",
    "requestId": "ccpa-req-001"
  }'
4
Get consent status
bash
curl http://localhost:3004/v1/consent/CUST-001
json
{
  "customerId": "CUST-001",
  "optedOutChannels": ["email", "sms"],
  "gdprErasureRequested": false,
  "ccpaDns": false,
  "lastUpdated": "2026-06-08T10:00:00Z"
}
5
List pending requests + SLA status
bash
curl http://localhost:3004/v1/consent/requests

Returns all pending GDPR/CCPA requests with SLA countdown, status (PENDING / IN_PROGRESS / COMPLETED), and responsible systems.

Identity Resolution

CDH Bridge resolves customer identity across anonymous sessions, authenticated sessions, and multi-system IDs using a probabilistic + deterministic matching engine built into the Profile Router.

How It Works

Match TypeIdentifiers UsedConfidenceAction
DeterministicExact email, phone, or externalId match1.0Auto-merge
High ProbabilisticName + address + device fingerprint0.85–0.99Auto-merge
Low ProbabilisticPartial name or device only0.50–0.84Queue for review
No MatchUnknown identifiers<0.50Create new profile

Identity Stitch Flow

text
Anonymous Visit              Login Event              Post-Login
─────────────────           ─────────────            ──────────────────────
cookieId: ck-abc123   ───►  customerId: CUST-001  ►  Merged profile
 5 page views               cookieId:   ck-abc123    All 5 pre-login events
 2 product views                    │                attributed to CUST-001
                               Identity              in Pega CDH IH
                               Stitch API            segment updated

Trigger Identity Stitch Manually

bash
curl -X POST http://localhost:3002/v1/profiles/stitch \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "CUST-001",
    "cookieId": "ck-abc123",
    "email": "alice@bank.com"
  }'

Get Identity Graph for a Customer

bash
curl http://localhost:3002/v1/profiles/CUST-001/identity-graph
ℹ️
The identity graph returns all known identifiers for a customer across systems — cookies, device IDs, external CRM IDs, email hashes — and their match confidence scores.

NexusJS SDK

NexusJS is a lightweight browser/Node SDK that wraps CDH Bridge APIs. Drop it into any web or mobile app to start tracking events and displaying NBA decisions.

Installation

bash
npm install @cdh-bridge/nexusjs
# or via CDN
<script src="https://cdh-bridge-demos.vercel.app/sdk/nexus.min.js"></script>

Initialise

javascript
import Nexus from '@cdh-bridge/nexusjs';

const nexus = new Nexus({
  eventCollectorUrl: 'https://your-cdh-bridge.com',
  apiKey: 'YOUR_API_KEY',   // omit for local dev
  debug: true               // logs events to console
});

// Set the current user (call after login)
nexus.identify('CUST-001', {
  email: 'alice@bank.com',
  firstName: 'Alice'
});

Track Events

javascript
// Track a page view
nexus.track('page_view', { page: window.location.pathname });

// Track a product view
nexus.track('product_view', {
  product: 'home-loan',
  rate: '4.2%',
  page: '/products/mortgages'
});

// Track an offer interaction
nexus.track('offer_accept', {
  decisionId: 'nba-uuid-here',
  action: 'HomeLoanOffer',
  treatment: 'FeaturedRate4.2'
});

Auto-tracking (zero-config)

javascript
const nexus = new Nexus({
  eventCollectorUrl: 'https://your-cdh-bridge.com',
  autotrack: {
    pageViews: true,        // tracks every route change
    clicks: '[data-track]', // tracks clicks on data-track elements
    forms: true             // tracks form submissions
  }
});

// In your HTML:
// <button data-track="offer_accept" data-product="home-loan">Apply Now</button>

React Hook

javascript
import { useNexus } from '@cdh-bridge/nexusjs/react';

function ProductPage({ product }) {
  const { track } = useNexus();

  useEffect(() => {
    track('product_view', { product: product.id });
  }, [product.id]);

  return <div>...</div>;
}
💡
Demo tip: The NexusJS SDK is already embedded in the DemoBank and Citadele demo apps at /sdk/nexus.js. Open the browser dev tools console to see real-time event tracking logs.

Troubleshooting

Common Issues

!
Services won't start — Docker Desktop not running
⚠️
Symptom: docker compose up -d fails with "Cannot connect to the Docker daemon"
bash
# macOS: Open Docker Desktop app, wait for whale icon to appear in menu bar
open -a Docker
# Wait ~30 seconds, then retry:
docker compose up -d
!
Port already in use
⚠️
Symptom: Error: listen EADDRINUSE :::3001
bash
# Find and kill what's using the port
lsof -i :3001
kill -9 <PID>

# Or stop all CDH Bridge containers
docker compose down
!
Events not appearing in Pega CDH
bash
# 1. Check Event Collector is healthy
curl http://localhost:3001/health

# 2. Check Mock CDH is healthy
curl http://localhost:3010/health

# 3. View Event Collector logs
docker compose logs --tail=50 event-collector

# 4. Check Kafka connectivity
curl http://localhost:3001/v1/events/kafka-status
!
Redis connection refused
bash
# Check Redis container
docker compose ps redis

# Restart Redis
docker compose restart redis

# Test Redis directly
docker compose exec redis redis-cli ping
# Expected: PONG
!
Profiles not merging / duplicate profiles
bash
# Check merge queue
curl http://localhost:3002/v1/profiles/merge-queue

# View merge logs
docker compose logs --tail=100 profile-router | grep MERGE

# Force a manual stitch
curl -X POST http://localhost:3002/v1/profiles/stitch \
  -H "Content-Type: application/json" \
  -d '{"customerId":"CUST-001","email":"alice@bank.com"}'
!
Full reset (nuclear option)
⚠️
This wipes all data and containers. Only use when you need a completely fresh state.
bash
docker compose down -v          # stop + remove volumes
docker compose up -d            # fresh start
node scripts/seed-data.js       # re-seed demo data
